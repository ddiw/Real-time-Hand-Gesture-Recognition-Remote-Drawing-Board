# 실시간 손 제스처 인식 원격 그림판

휴대폰 카메라에 손을 비추면 허공에 그린 선이 PC 화면의 캔버스에 나타납니다.
앱 설치나 별도 장비 없이 브라우저만으로 동작하며, 손가락 개수로 그리기·지우기·
확대·초기화를 구분합니다.

```
휴대폰 브라우저 ──HTTPS/WSS──> 웹 게이트웨이 ──> 영상 분석 ──> 패턴 판정 ──> 캔버스 ──> PC 모니터
   (카메라)                      (0-web)      (MediaPipe)    (제스처 규칙)   (OpenCV)
```

---

## 1. 결과 요약

| 항목 | 값 |
| --- | --- |
| 손 랜드마크 추론 | p50 **15ms** / p95 **47ms** (CPU, 640×480) |
| 휴대폰 전송률 | 기본 15 FPS (`?fps=N`으로 1~30 조절) |
| 인식 대상 | 한 손, 21개 랜드마크 |
| 명령 | 그리기 · 지우기 · 확대 · 축소 · 초기화 |
| 서비스 구성 | 컨테이너 4개, WebSocket 3구간 |
| 자동 테스트 | **84개** (제스처·캔버스 41 / 영상 분석 43) |

구현된 것

- 휴대폰 전면 카메라 프레임을 실시간으로 받아 손 랜드마크를 추출하고 명령으로 판정
- 판정 결과를 OpenCV 캔버스에 반영하고, 그 화면을 PC 모니터로 다시 스트리밍
- 모니터에서 원본 영상 위에 **판정에 사용된 21개 랜드마크 골격**을 겹쳐 표시
- 명령·모드·손가락 개수·줌 배율·지연·수신 FPS 실시간 계측
- 모니터 버튼으로 확대/축소/초기화/PNG 저장, 펜 색상 6종 선택
- 저장한 그림을 서버에 보관하고 웹 갤러리에서 다시 열람

## 2. 시스템 구조

네 개의 컨테이너가 각각 하나의 책임만 가집니다.

| 컨테이너 | 포트 | 역할 |
| --- | --- | --- |
| `0-web` | 8000 | 휴대폰 촬영 페이지, PC 모니터, QR 발급, 프레임 중계, 저장 파일 관리 |
| `2-vision-analysis` | 8760 / 8762 | MediaPipe Hand Landmarker로 21개 랜드마크 추출 (8762는 health·metrics) |
| `3-pattern-command` | 8761 | 랜드마크를 제스처 명령으로 판정 |
| `1-canvas` | 8770 | 명령을 OpenCV 캔버스에 적용하고 결과 이미지 반환 |

### 구간별 계약

**웹 → 영상 분석** (`ws://vision-analysis:8760/ingest/{session_id}`)

프레임마다 메시지 두 개를 순서대로 보냅니다. TEXT로 JSON 헤더
(`session_id`, `seq`, `capture_ts`, `width`, `height`, `format`, `rotation`,
`mirrored`), 이어서 BINARY로 `width × height × 3` 바이트의 raw BGR 픽셀.

**영상 분석 → 패턴 판정** (`ws://pattern-command:8761/landmarks`)

`hand_present`, `landmarks`(화면 정규화 좌표 21개), `world_landmarks`(3D 월드
좌표 21개), `hand_scale`, `quality`를 담은 JSON. 손이 없으면 좌표 필드는
`null`이며, 이 규칙은 계약 수준에서 강제됩니다.

**패턴 판정 → 캔버스** (`ws://canvas:8770/commands/{session_id}`)

`command`, `mode`, `seq`, `index_tip`, `index_direction`, `finger_count`,
`landmarks`를 담은 JSON. 캔버스는 이 명령을 실행만 하고 제스처를 다시 판단하지
않습니다.

## 3. 제스처 규칙

손가락은 **검지 → 중지 → 약지 → 새끼 순서로만** 셉니다. 엄지는 세지 않습니다.
새끼만 편 자세처럼 순서를 건너뛴 조합은 명령을 만들지 않습니다.

| 자세 | 명령 | 비고 |
| --- | --- | --- |
| 주먹 (0개) | `CLEAR` | 그림과 배율 초기화. 13프레임 유지해야 발동 |
| 1개 | `DRAW` | 검지 끝 좌표를 이어 선을 그림 |
| 2개 | `ERASE` | 해당 위치 주변을 지움 |
| 3개 + 좌로 이동 | `ZOOM_IN` | |
| 3개 + 우로 이동 | `ZOOM_OUT` | |
| 그 외 | `IDLE` | |

각 손가락은 PIP 관절 각도가 120도 이상이면 펴짐으로 보고, 최근 5프레임 중
4프레임 이상 같은 결과일 때 확정합니다. 모드 락이 없어 자세가 바뀌면 그 프레임에
바로 명령이 바뀝니다.

### 줌 판정

3손가락 자세를 잡는 순간의 손 위치를 **중립점**으로 잡고, 그 좌우로 데드존을
벗어나 머무는 동안 계속 확대·축소합니다. 가운데로 돌아오면 멈추고, 반대편으로
넘어가야 방향이 바뀝니다.

```
ratio = (손목#0.x + 검지MCP#5.x + 새끼MCP#17.x) / 3 / 화면상 손바닥 너비
```

손바닥 너비로 나누므로 카메라와의 거리가 변해도 감도가 같습니다.

## 4. 설계에서 판단한 것

**제스처 판정은 한 곳에서만 한다.** 캔버스는 명령을 실행할 뿐 손 모양을 다시
해석하지 않습니다. 규칙을 바꿀 때 고칠 파일이 하나로 유지됩니다.

**손가락 펴짐은 3D 월드 좌표로, 좌우 이동은 화면 좌표로 판정한다.** 월드 좌표는
손 중심 기준이라 검지가 카메라를 향해도 각도가 무너지지 않지만, 손이 화면을
가로질러도 값이 변하지 않습니다. 두 좌표계를 목적에 따라 나눠 씁니다.

**추론 중 도착한 프레임은 최신 것만 남기고 버린다.** 처리 속도보다 입력이 빠를 때
큐가 무한히 쌓이는 대신 지연이 일정하게 유지됩니다.

**전면 카메라 프레임은 보내기 전에 좌우 반전한다.** 손을 오른쪽으로 옮기면 펜도
오른쪽으로 가고, 이후 모든 단계가 추가 보정 없이 일관됩니다.

**지연은 한 시계로만 측정한다.** 휴대폰 시각과 PC 시각의 차이는 지연이 아니라
두 기기의 시계 오차를 포함합니다. 게이트웨이가 프레임을 받은 시각과 그 결과가
돌아온 시각을 비교해 실제 왕복 시간만 계측합니다.

**초기화에는 두 개의 가드를 둔다.** 손가락 안정화 창이 채워지기 전에는 모든
손가락이 접힌 것으로 보고되므로, 손이 화면에 들어올 때마다 주먹으로 오인해
캔버스를 지우는 문제가 있었습니다. 워밍업 13프레임과 주먹 유지 13프레임을 각각
두어 서로 다른 오작동을 막습니다.

## 5. 사용 방법

### 5.1 준비

Python 3.12와 웹캠 대신 사용할 휴대폰이 필요합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\download_model.ps1
```

`download_model.ps1`은 MediaPipe Hand Landmarker 모델을
`containers/2-vision-analysis/models/`에 내려받습니다.

### 5.2 로컬 실행

```powershell
.\start_local.ps1
```

출력된 `Monitor` 주소를 PC 브라우저에서 엽니다. 휴대폰 연결은 HTTPS가 필요하므로
아래 ngrok 방식을 사용합니다.

### 5.3 휴대폰까지 연결

휴대폰 카메라 권한은 보안 컨텍스트(HTTPS)에서만 허용되므로 터널이 필요합니다.

```powershell
.\start_local.ps1 -Ngrok -NgrokPath .\tmp\ngrok\ngrok.exe
```

1. 출력된 `Monitor` 주소를 PC에서 엽니다.
2. 화면의 QR을 휴대폰으로 스캔합니다.
3. 휴대폰에서 **카메라 시작**을 누르고 카메라 권한을 허용합니다.
4. 휴대폰 카메라에 손을 비추면 PC 모니터에 원본과 캔버스가 함께 나타납니다.

전송률을 조절하려면 휴대폰 주소에 `&fps=N`을 붙입니다 (1~30, 기본 15).

### 5.4 Docker 실행

```powershell
$env:SESSION_TOKEN = "hand-board"
$env:PUBLIC_BASE_URL = "https://실제-ngrok-주소"
docker compose up -d --build
```

개발 중에는 `docker-compose.override.yml`이 자동으로 적용되어 소스를 마운트하고
저장할 때마다 서비스를 재시작합니다. 이 동작 없이 실행하려면
`docker compose -f docker-compose.yml up`을 사용합니다.

### 5.5 조작

**손으로**

| 하고 싶은 것 | 손 모양 |
| --- | --- |
| 그리기 | 검지 하나 |
| 지우기 | 검지 + 중지 |
| 확대 | 손가락 셋을 편 채 왼쪽으로 |
| 축소 | 손가락 셋을 편 채 오른쪽으로 |
| 전체 지우기 | 주먹을 약 1초 유지 |

**모니터 화면에서**

- **확대 / 축소 / 초기화** — 휴대폰이 연결돼 있지 않아도 동작합니다
- **PNG 저장** — 줌 표시와 커서가 없는 원본 해상도로 저장되며, 브라우저로 바로
  내려받아지고 하단 갤러리에 남습니다
- **펜 색상** — 6가지 중 선택. 색을 바꾸면 진행 중인 획이 끊기므로 한 선은 한 색을
  유지합니다

상태 패널에서 명령, 모드, 인식된 손가락 개수, 줌 배율, 왕복 지연, 수신 FPS를
실시간으로 볼 수 있습니다. 원본 화면 위의 골격은 판정에 실제로 사용된 좌표입니다.

## 6. 설정

환경 변수로 조절합니다. 괄호 안은 기본값입니다.

**제스처 판정**

| 변수 | 설명 |
| --- | --- |
| `ZOOM_DEADZONE_RATIO` (0.15) | 중립점에서 이만큼(손바닥 폭 단위) 벗어나야 줌 시작 |
| `CLEAR_HOLD_FRAMES` (13) | 주먹을 이 프레임 수만큼 유지해야 초기화 |
| `WARMUP_FRAMES` (13) | 손이 새로 잡힌 뒤 초기화를 허용하기까지의 프레임 |
| `FINGER_WINDOW` (5) | 손가락 상태 안정화 창. 늘리면 안정적, 전환은 느려짐 |
| `FINGER_OPEN_VOTES` (4) | 창 안에서 펴짐으로 판정할 최소 횟수 |

**영상 분석**

| 변수 | 설명 |
| --- | --- |
| `VISION_TARGET_WIDTH` / `HEIGHT` (640 / 480) | 추론 입력 해상도 |
| `VISION_MIN_DETECTION_CONFIDENCE` (0.7) | 손 검출 임계값 |
| `VISION_DELEGATE` (CPU) | 추론 디바이스 |

## 7. 테스트

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m pytest containers\2-vision-analysis\tests -q
```

제스처 규칙과 캔버스 41개, 영상 분석 계약·전처리·필터 43개, 합계 84개입니다.
제스처 테스트는 손가락 개수별 명령, 자세 전환, 줌 중립점 재설정, 초기화 가드 등
규칙의 경계 조건을 다룹니다.

## 8. 알려진 제한

- 인식 대상은 한 손입니다.
- 세션은 단일 공개 토큰을 사용합니다. 터널 주소를 아는 사람은 촬영 엔드포인트에
  연결할 수 있으므로, 공개된 곳에 주소와 토큰을 함께 적지 않습니다.
- 게이트웨이가 영상 분석으로 raw BGR을 전달하므로 프레임당 약 900KB가 오갑니다.
  같은 호스트에서는 문제가 없지만 전송량을 줄일 여지가 있습니다.
- 모니터 접속자 수만큼 프레임이 복제 전송되므로 터널 대역폭에 영향을 줍니다.
- 종단 지연에는 터널 왕복이 포함되며, 같은 네트워크에서 직접 연결하면 줄어듭니다.
  다만 휴대폰 카메라 권한 때문에 HTTPS 인증서가 필요합니다.
